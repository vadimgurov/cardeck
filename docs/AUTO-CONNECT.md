# Автоматическое подключение при посадке в машину (просыпайтесь по автомобильной трансляции Bluetooth ACL)

> 23 октября 2026 г. Цель: держа телефон в кармане, откройте дверь автомобиля → Bluetooth-соединение с автомобилем → CarDeck автоматически загрузится и запустится.
> Сеанс CarPlay. Код: `bt/CarBluetoothReceiver` + `CarPlayService.ACTION_AUTO_START_SESSION`.

## 1. Трансляция: Почему статическая регистрация списка может вызвать убитый процесс?

`BluetoothDevice.ACTION_ACL_CONNECTED` / `ACTION_ACL_DISCONNECTED` в
[Список неявных широковещательных исключений ](https://developer.android.com/develop/background-work/background-tasks/broadcasts/broadcast-exceptions)
(Android 8+ накладывает ограничения на неявную трансляцию регистрации манифеста, эти два являются исключениями). Итак, пока устройство осуществляет трансляцию,
Система поставит:

```
<receiver android:name=".bt.CarBluetoothReceiver" android:exported="true">
    <intent-filter>
        <action android:name="android.bluetooth.device.action.ACL_CONNECTED" />
        <action android:name="android.bluetooth.device.action.ACL_DISCONNECTED" />
    </intent-filter>
</receiver>
```

При доставке в процесс с холодным запуском никаких действий на переднем плане не требуется.

## 2. Служба регистрации: настоящий источник иммунитета — не Bluetooth.

**В списке исключений для фонового запуска FGS для Android 12+** нет пункта «Bluetooth Broadcast» (см. официальный список).
[Ограничения на запуск службы переднего плана из фонового ](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start)).
Непосредственно `startForegroundService` из трансляции ACL будет заменен на `ForegroundServiceStartNotAllowedException`.
Блокировать — **если** приложение не соответствует одному из пунктов списка. Данный проект отвечает следующим требованиям:

> **Ваше приложение имеет разрешение SYSTEM_ALERT_WINDOW.**

Темный экран (`ScreenDimmer`) и сенсорный датчик изначально должны «отображаться поверх других приложений», поэтому это исключение установлено естественным образом.
(targetSdk 34 требует только наличия разрешений; Android 15+ дополнительно требует **видимое** плавающее окно в данный момент – этот проект
targetSdk 34 не затронуты этим дополнением).

Выводы и контрмеры:

- Когда пользователь **не дает** разрешение плавающему окну, автоматический запуск не удастся → `CarBluetoothReceiver` фиксирует исключение и записывает журнал
  (Просто откройте приложение вручную и подключитесь один раз, и в этот раз активность будет видна);
- Тип FGS должен быть `connectedDevice` (2 параметра `startForeground` использовать нельзя)
  `mediaProjection` — Android 14 проверит AppOps PROJECT_MEDIA на наличие последнего и сразу же выйдет из строя).
  `CarPlayService.onStartCommand` в этом проекте исправлен на `FOREGROUND_SERVICE_TYPE_CONNECTED_DEVICE`.

## 3. Фильтрация целей (во избежание ложного срабатывания наушников/часов)

`CarBluetoothReceiver.isCarDevice`:

1. Пользователь выбрал **целевой автомобиль** (`TargetDevicePrefs`) в «Сопряжение Bluetooth» → распознает только этот MAC;
2. Нет выбора → Чтобы узнать, нажмите имя Bluetooth и ключевое слово (BMW / MINI / AUDI / PORSCHE / MERCEDES / BENZ / VOLVO /
   КАРПЛЕЙ).

Вы можете получить `BluetoothDevice` только в трансляции ACL (для всех `address` / `name` требуется `BLUETOOTH_CONNECT`,
Просто сдавайтесь без авторизации - невозможно определить, машина это или нет).

## 3.1 Переключатель

**Настройки → Дисплей → «Автоматически подключаться при посадке в машину» (вкл/выкл, по умолчанию включено)**, сохранение в
`AutoConnectPrefs.enabled` (предпочтение `settings`, ключ `auto_connect_on_bt`).
Получатель считывает широковещательную рассылку ACL каждый раз, когда получает ее (возможно, процесс был только что запущен из холодного состояния и кэша нет). Отключить трансляцию после ACL
Он все равно прибудет, но вернется напрямую, без запуска какой-либо службы.

## 4. Выбор времени

```
Автомобильный Bluetooth ACL подключен
  → CarBluetoothReceiver (статический манифест, процесс можно запустить в холодном состоянии)
  → startForegroundService(ACTION_AUTO_START_SESSION)
  → CarPlayService.onStartCommand: startForeground(connectedDevice) + удерживать блокировку в течение 5 с.
  → SessionController.ensure(applicationContext) //Сначала создайте объект сеанса во время холодного запуска!
  → Тихо получить MediaProjection (см. §4.1) → audioEnabledForSession = успешно ли оно
  → SessionController.startConnection(applicationContext) // Та же ссылка, что и «Начать подключение» на главной странице.

Автомобильный Bluetooth ACL отключен
  → ACTION_AUTO_STOP_SESSION (startService: процесс уже находится в состоянии приоритетной службы, когда служба запущена, разрешено)
  → SessionController.disconnect() (завершить сеанс, освободить виртуальный экран, восстановить экран/тайм-аут, остановить службу)
```

## 4.1 Silent MediaProjection (автоматическое подключение «звука»)

AudioPlaybackCapture должен иметь экземпляр MediaProjection, а токен должен быть **single** (будет признан недействительным при остановке захвата).
Никто не может нажать «Разрешить зеркалирование экрана» во время автоматического подключения. Две системные ворота и средства противодействия (`audio/SilentProjectionActivity`):

1. **Всплывающее окно авторизации** → Шизуку выполняет `appops set <pkg> PROJECT_MEDIA allow`: SystemUI
   Когда `MediaProjectionPermissionActivity` увидит эту операцию приложения, он сразу вернется в `RESULT_OK` без всплывающего окна.
   (Тот же подход, что и в официальной документации Tasker).
2. **Начать активность в фоновом режиме (BAL)** → Казнь Шизуку
   `am start -n <pkg>/<activity> --activity-no-animation`: оболочка удерживается
   `START_ACTIVITIES_FROM_BACKGROUND`, не ограниченный BAL на стороне приложения (поэтому действие должно
   `exported=true` — оболочка не имеет `START_ANY_ACTIVITY`); возвращается в приложение в случае сбоя
   `startActivity` (требуется `SYSTEM_ALERT_WINDOW`, если его нет, сначала будет указан `appops`).

Сама страница: 1×1, без касания/фокуса, без анимации, `noHistory` + `excludeFromRecents` +
`taskAffinity=""`; `setShowWhenLocked/setTurnScreenOn` гарантирует, что обратный вызов может быть выполнен, даже если телефон заблокирован и находится в кармане.

В Android 14 действует **железный закон**: после получения авторизации необходимо** сначала обновить тип FGS, чтобы включить
`mediaProjection`** можно использовать для настройки `getMediaProjection()`; добиться прямого мультиплексирования
`pendingProjectionResult → upgradeToProjection() → takeProjection()`.
Кроме того, когда `startForeground` повторяется в `CarPlayService.onStartCommand`, если
`mediaProjection != null` должен продолжать выводить этот тип, иначе это будет эквивалентно удалению типа и проецирование будет остановлено системой.

**Побочные эффекты**: `appops set PROJECT_MEDIA allow` **постоянен** (appops.xml), то есть после этого приложения.
Вы можете транслировать экран беззвучно; очистите его вручную, когда он не нужен: `adb shell appops set <pkg> PROJECT_MEDIA default`.

## 5. Известные ограничения

1. **Голос зависит от онлайн-активности Сидзуку**: токен экрана молчаливого ведущего имеет вид `appops` + `am start`; когда Шизуку недоступна
   Автоматическое подключение по-прежнему может передавать видео (активно отключая звук без всплывающих окон). `RECORD_AUDIO` попробует первым, если не будет одобрено
   Дополнительная награда `appops set RECORD_AUDIO allow`.
2. **Необходимо запустить Shizuku**: внедрение виртуального экрана/сенсорного ввода зависит от разрешения оболочки; когда Шизуку не запускается после перезагрузки телефона
   Автоматическое соединение останавливается на сообщении «Bluetooth подключен, экран автомобиля черный». `ШИЗУКУ: Служба не работает` выступления в журнале.
3. **Первое соединение может один раз прерваться**: окно службы iAP2 может быть не готово при первом включении автомобиля, и существующий клиент BT автоматически повторит попытку;
   `BT-C: Соединение не удалось...`.
4. **Выйти и прибраться**: `ACL_DISCONNECTED` → `disconnect()`. Если в это время ведется потоковая передача, `onEnded` и
   `disconnect` будет запускаться один за другим (отметка `phoneScreenOff` гарантированно собирается только один раз).
5. Автоматический запуск без появления какого-либо интерфейса; если пользователь хочет узнать, что произошло, посмотрите уведомление («CarDeck работает») или журнал.

## 6. Устранение неполадок

Журнал приложения (`files/main_debug.log`):

```
АВТО: Bluetooth автомобиля подключен к BMW 87866 (AA:BB:CC:DD:EE:FF) — сеанс автоматически запускается.
АВТО: игнорировать неавтомобильные Bluetooth FreeBuds Pro (…)
АВТО: автоматический запуск был перехвачен системой (ForegroundServiceStartNotAllowedException: ...) — разрешите «Отображать поверх других приложений».
SVC: Получить «Автоматически запускаться при посадке в машину» — начать сеанс
АВТО: Bluetooth автомобиля отключен...——Завершить сеанс.
```

Проверка командной строки:

```bash
# Зарегистрирован ли получатель (приемник в списке появится в дампе пакета)
adb shell dumpsys package io.github.shaonialife.cardeck | grep -i -A3 CarBluetoothReceiver
# Один раз включите и выключите питание Bluetooth автомобиля и посмотрите, есть ли в журнале две строки AUTO:/SVC:.
```

> **Не** используйте `am broadcast -a …ACL_CONNECTED -n <pkg>/.bt.CarBluetoothReceiver` для моделирования:
> `EXTRA_DEVICE` является посылочным, `am` не может быть передан, и получатель вернется напрямую, если он не сможет получить устройство, что выглядит как «неэффективное».
