# Автомобильный HID-вход: мультимедийные клавиши на руле + ручка iDrive (BMW iD8.5)

> 23 октября 2026 г. Цель: рулевое колесо для переключения песен/паузы (глобальные мультимедийные клавиши), вращение ручки iDrive и четырехпозиционный переключатель (навигация по фокусу на виртуальном экране).

## 1. Ссылка (текущий статус = отремонтированная деталь)

```
Автомобиль/информация → hidDevices[] (uuid + hidDescriptor)
  → Отправьте hidSetInputMode(mode=0) **каждому** uuid при установлении сеанса ← Все устройства были пройдены уже давно
  → Автомобиль начинает отправлять hidSendReport (канал событий)/0x6802 AccessoryHIDReport (туннель iAP2)
  → Разделить трафик по **дескриптору устройства** (не по uuid, не по модели автомобиля):
       Страница потребителя 0x0C → MediaKey (глобальное распространение AudioManager, фокус не требуется)
       Страница дигитайзера 0x0D → Touch (введение координат TouchRouter)
       Общий рабочий стол 0x01 → Ручка/Четыре направления (на этот раз добавлено недавно, DPAD вводится в виртуальный экран)
```

**Не меняйте его на «угадать устройство по uuid/имени»**: `uuid` является необязательным для каждого автомобиля (Audi отправляет `"0"/"1"`, DiPlay отправляет целое число),
Дескриптор является единственным стабильным сигналом (`ConsumerKeys.parseDescriptor`/`HidNavigation.isNavigationDevice`).

## 2. Медиа-ключи (существующие)

`ConsumerKeys` анализирует дескриптор, чтобы получить массив Usage, который декодируется отдельно в соответствии с двумя семантиками HID **Array/Variable**.
(Массив: байт = индекс; Переменная: 1 бит на использование), затем отобразите `KEYCODE_MEDIA_*`,
Распространяется по всему миру `SessionController.dispatchMediaKey` → `AudioManager.dispatchMediaKeyEvent`.
(Это действует везде, где находится фокус, и песни также можно переключать, когда автомобильно-машинный интерфейс остановлен в навигации).

## 3. Ручка/четырёхпозиционная (на этот раз добавлена недавно)

`input/HidNavigation` определяет навигационное устройство: дескриптор имеет страницу Generic Desktop 0x01 и содержит
**Колесо (0x38) или шляпа (0x39)**, а не страница дигитайзера (кроме сенсорного экрана).

Анализ сообщения (если дескриптор отсутствует, используйте 2–4 байта для покрытия):

| Расположение | Семантика |
|---|---|
| Последний байт | **Подпись** Шаг ручки (положительный = по часовой стрелке → DPAD_DOWN, отрицательный → DPAD_UP, до 5 шагов в одном кадре) |
| Предыдущие байты | Растровое изображение кнопки, триггер **нарастающего фронта**: бит0=подтверждение, 1=вверх, 2=вниз, 3=влево, 4=вправо, 5=возврат |
| Шляпное устройство (0x39, 1 байт) | Младшие 4 бита = 8-позиционная шляпа (0 вверх / 2 вправо / 4 вниз / 6 влево, остальное = свободно) |

Внедрить `ICarInput.keyEvent(displayId, keyCode)` (`injectInputEvent` UserService,
`KeyEvent.setDisplayId` указывает прямо на виртуальный экран, миллисекундный уровень); не удается вернуться к `input -d <id> keyevent <code>`.
Целевой экран = `VirtualLauncher.activeAppDisplayId()` (сетка рабочего стола/экран открытого приложения).

**Почему DPAD нельзя распространять глобально**: DPAD требует системы фокусировки, и глобальное распространение будет осуществляться на главном экране телефона; только при введении в
Только виртуальный экран автомобиля-машины может обеспечить отзывчивость рабочего стола/приложения автомобиля-машины.

## 4. Подсветка фокуса (видимость ручки)

- `res/drawable/focus_ring.xml`: при `state_focused` рисуется только голубая обводка 3dp;
- Сетевой блок (`GridActivity.PageHolder.bind`): `isFocusable = true`+
  `foreground = focus_ring` (передний план не отменяет фон, заданный кодом);
- Событие ключа автоматически приведет к выходу окна из сенсорного режима (`focusableInTouchMode=false` может получить фокус).

**Известные ограничения**: док-станция представляет собой **независимый дисплей**, DPAD не перемещает фокус между экранами — ручка может находиться только на экране приложения.
Двигайся. Чтобы поддержать функцию «нажмите ручку влево, чтобы перейти к док-станции», стороне запуска необходимо перехватить край DPAD и переключить экран/изменить фокус.
Не реализовано (прежде чем продолжить, необходимо подтвердить это на реальной машине).

## 6. Устранение неполадок, быстрая проверка

| Феномен | Первый взгляд |
|---|---|
| Никаких журналов | Есть ли у `/info` hidDevices? Отправляется ли `hidSetInputMode` каждому uuid |
| Есть HID-RAW, но нет ответа | Распознается ли дескриптор как Consumer/Navigation (байты `desc=` в журнале + результат анализа) |
| На ручке есть бревно, но фокус не перемещается | Может ли виртуальный экран сфокусировать вид (модуль сетки `isFocusable`) и правильно ли введенный displayId |
| Переключение песен на рулевом колесе недействительно | Вызывается ли `dispatchMediaKey`; существует ли текущий медиа-сеанс системы |
