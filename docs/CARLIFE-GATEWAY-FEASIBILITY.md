## 1. Соглашение CarLife: почти полностью публичное

Baidu полностью внедрила автомобильный терминал с открытым исходным кодом на GitHub ApolloAuto/apollo-DuerOS в 2018 году.
(Исходный репозиторий был удален, но сохранилась 81 ветвь, например, milking/apollo-DuerOS, Apache 2.0 можно легально использовать повторно).

- **Передача**: 7 каналов TCP - мониторинг мобильного телефона 7240(CMD)/8240(ВИДЕО)/9240(МЕДИА)/
  9241(TTS)/9242(VR)/9340(СЕНСОР)/9440(CTRL); Режим Wi-Fi = приемник активно подключается
  Прямое соединение TCP «Mobile IP:Port» (ADB не требуется; используйте только ADB Forward/AOA в режиме USB)
- **Сообщение**: Protobuf + пользовательский заголовок; Идентификатор сообщения измерен и известен: согласование версии 98305/65538,
  Аутентификация 98380/65611, пульс 131074, касание 425985, аппаратная клавиша 425992; рукопожатие 8 этапов
- **Медиа**: видео = чистый поток H.264/AVC Приложение B, закодированный отправителем (величина 720p/30 кадров в секунду);
  Аудио PCM/AAC; контрольный протобуф
- **Touchback**: независимый сенсорный канал, координаты преобразуются в соответствии с разрешением проекционного экрана — просто подключите к нашему HID-контакту CarPlay.

## 2. Ключевой пробел: на каком канале работает Amap?

- **CarLife+ по умолчанию не поддерживает проекцию экрана Amap** (подходит только для приложений Baidu). Обходной путь: CarLife+ 8.0.
  Мобильное приложение «Экран-зеркало» отображает полноэкранный режим (включая Amap) или разблокировка USB «Super Mirror» — возможности режима зеркалирования ограничены.
- **Проекция экрана Amap во всю глубину на канале CarWith/ICCOA Carlink** (уровень полосы движения/круиз/полный пользовательский интерфейс мобильной версии),
  Это соглашение: спецификации могут быть загружены только членами альянса, реализованы с нулевым открытым исходным кодом и включают аутентификацию и шифрование; сообщество может только повернуть вспять
  Мобильная версия CarWith/Jovi или автомобильная версия APK, распространяемая Ensan
- **Вход «CarLife Connection» зарезервирован в Xiaomi CarWith** (встроенный компонент com.baidu.carlife)——
  То есть только реализация принимающей стороны CarLife может сначала охватить режим совместимости CarWith; то же самое относится и к Honor AutoLink (совместим с CarLife)
- Подводные камни в новой версии: приложение CarLife ≥7.2 несовместимо со сторонними автомобильными терминалами и черным экраном; надежный отправитель =
  Соединение CarWith CarLife, старая версия приложения CarLife (≤6.7.2), режим совместимости с автомобильным подключением каждого производителя (требуется фактическое тестирование)

## 3. Возможность использования шлейфа на одной машине (основные инновации и риски этого решения)

- Плоскость данных режима CarLife WiFi = прямое соединение TCP с IP-адресом мобильного телефона → 127.0.0.1 теоретически доступен напрямую
  (Песочница Android позволяет осуществлять связь между приложениями на локальном хосте без пересылки adb - самостоятельную пересылку невозможно выполнить без root)
- **Никто публично не подтвердил петлю на той же машине**. Риск полностью заключается в конечном автомате отправителя:
  Приложение-отправитель (встроенный модуль CarLink/CarLife/Amap) может потребовать «Обнаружено подключение USB» или
  «Подключиться к автомобильной точке доступа», чтобы активировать услугу мониторинга/принять соединение.
- Реальный метод измерения (эксперимент «Go/No-Go»): Установите старую версию приложения CarLife на свой мобильный телефон → Откройте интерфейс подключения →
  Подключите локальный браузер/другое приложение к адресу 127.0.0.1:7240, чтобы проверить, есть ли услуга; или воспользуйтесь им сначала
  carlife_pc_tool Проверьте отправителя мобильного телефона на ПК, а затем переместите его обратно на тот же компьютер.
- **Резервная архитектура** (при сбое шлейфа): установите полную версию приложения на резервный телефон (приемник CarLife +
  отправитель CarPlay) постоянно в автомобиле = собственная версия Tbox box (CarLifeWirelessBox проверил эту топологию,
  Затем мы можем добавить конец отправки CarPlay) - это именно форма коммерческого продукта.

## 4. Интеграция с существующими проектами (если реализовано)

```
┌──────────────────── Тот же телефон Honor ───────────────────┐
│ Приложение Honor CarLink/CarLife (отправитель) │
│ ↕ 127.0.0.1:7240… (режим CarLife WiFi) │
│ carlife/ Модуль: Приемник CarLife (новый) │
│ - Рукопожатие/Аутентификация/Первый сигнал (protobuf) │
│ - Потоковая передача H.264 Приложение B → remux (нулевое транскодирование) │
│ - коснитесь 425985 ← Преобразование координат контакта CarPlay HID │
│ Bridge/: передать ремультиплексированный поток TS отправителю CarPlay │
│ ↕ Bluetooth RFCOMM + Wi-Fi + мастер-сессия AirPlay │
└───────────────────────→ Автомобильный экран Audi ──────────────────────┘
```

Предлагаемая последовательность реализации: сначала проведите «эксперимент с обратной связью Go/No-Go» (1–2 дня) → приемник CarLife.
(Повторное использование библиотеки apollo-DuerOS C++ или реализации CarLifeWirelessBox Kotlin, 2–3 недели) →
remux Bridge (1 неделя) → Интерфейсы с отправителем CarPlay фазы 2.

## 5. Сравнение с альтернативными маршрутами (важно)

| Маршрут | Опыт AutoNavi | Количество проектов | Риск | Задержка |
|---|---|---|---|---|
| A. AutoNavi Navigation SDK со встроенным пользовательским интерфейсом | Профессиональная навигация, управляемая через пользовательский интерфейс, но не «полный AutoNavi» | Малый (физические лица могут подать заявку на получение ключа) | Низкий | Один уровень, самый низкий |
| B. CarLife Gateway (данное исследование) | Приложение Baidu + режим зеркала Amap | Средний | Средний (совместимость отправителей) | Двухуровневый ~200-400мс |
| C. Шлюз Carlink (обратный) | Полная глубокая адаптация Amap (оптимально) | Большой | Высокий (закрытый исходный код + шифрование + фрагментация) | Двухуровневый |
| D. Купить коробку Tbox | В комплекте (коробка встроенная B+C) | Нулевое развитие | Низкий | Уровень коробки |

**Рекомендация**: немедленно выполните A в качестве базового плана (он не конфликтует с B/C и изначально является содержимым пользовательского интерфейса, нарисованного самостоятельно на этапе 2);
B запускается как усовершенствование после завершения фазы 2 (сначала запустите эксперимент с обратной связью); C оценивается только в том случае, если после проверки B сохраняется высокий спрос.

## 7. Примечания о соответствии

- apollo-DuerOS (Apache 2.0) и CarLifeWirelessBox (MIT) можно легально использовать повторно, при этом заголовок об авторских правах сохраняется.
- Reverse CarWith/Carlink APK, Enshan Circulation APK: только для личного исследования, не отделяется и не распространяется.
- «CarLife» является торговой маркой Baidu, для коммерческого использования требуется разрешение; пожалуйста, избегайте называть личные проекты.
