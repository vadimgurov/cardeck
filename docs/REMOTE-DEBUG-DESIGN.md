# Мост удаленной отладки CarDeck (вариант RemoteDebug + cardeck-bridge)

> 20.10.2026 Доработан дизайн и запущена первая версия. Цель: удаленное устранение неполадок для гонщиков - компьютер разработчика проникает через интранет.
> Предоставляя услуги отладки, пользователи могут установить **вариант RemoteDebug** на свои мобильные телефоны, указав адрес + код сопряжения для доступа; разработчик
> (или агент AI) Просматривайте журналы в режиме реального времени, вводите команды белого списка, отправляйте плавающие запросы и переустанавливайте новые пакеты одним щелчком мыши.

## Общая топология

```
Автомобильная машина ←→ Мобильный телефон [вариант удаленной отладки .rd] ←WSS/WS── Проникновение во внутреннюю сеть ── Компьютер разработчика
                                                    ├─ Поверхность оборудования WS (:8787)
                                                    ├─ Поверхность агента MCP (stdio)
                                                    └─ GET /apk/<file> (переустановить и распространить)
```

## Ключевые решения и причины

1. **Создайте вариант изолированного продукта вместо нового модуля/нового склада**: измерение `bridge`, `standard`
   (ежедневно/выпуск, имя пакета остается неизменным — авторизация Shizuku предоставляется по имени пакета) с `remote` (`applicationIdSuffix
   = ".rd"`, устанавливается одновременно с ежедневной версией). Код моста отладки находится в `app/src/remote/`, используется для зависимостей.
   `remoteDebugImplementation` —— **Одна строка не входит в стандартный продукт** (сборка проверена).
   Наложение манифеста (`tools:replace="android:name"`) заменяет класс приложения на
   `BridgeApp` и объявите `REQUEST_INSTALL_PACKAGES` с эксклюзивными компонентами отладки.
2. **Между стороной приложения и бизнес-кодом имеется только две поверхности связи**: `DebugFileLog.tap` (журнал добавлен основным
   Серийный номер + привязка для прослушивания, стандарт всегда равен нулю (нулевые издержки) и `BridgeCommands` (корректировка уже общедоступна)
   API `SessionController.ensure/startConnection/disconnect/statusLine`).
   Основная сторона не распознает ни один тип моста.
3. **Почерк WS-клиента (~200 строк подмножества RFC6455)**: не ссылается на okhttp – не зависит от ежедневных пакетов,
   Форму сообщения можно контролировать самостоятельно (текстовый фрейм/маска/пинг-понг/фрагментация на стороне сервера). работающая система wss
   SSLSocketFactory (проникающие службы для предоставления действительных сертификатов), в сценариях самоподписанного/голого IP используется ws://.
4. **Независимый склад на стороне сервера `cardeck-bridge` (MIT)**: Узел/TS, один процесс, двусторонний - сторона устройства WS
   + Поверхность агента MCP (stdio) + Статическая доставка APK. Кольцевой журнал 5000 строк/устройство с дедупликацией seq;
   Код сопряжения, одноразовое рукопожатие; Белый список команд (никогда не отпускайте оболочку).
5. **Три страховки для переустановки замкнутого цикла**: проверка sha256 для отклонения неправильных пакетов; **Контроллер сеанса.
   Disconnect` отключает все виртуальные экраны** (в противном случае всплывающее окно подтверждения установки системы переместится на виртуальный экран со стороны автомобиля——
   АГЕНТЫ записали ямы); перед установкой напишите пометку `resumePending`, и новая версия сначала запустится с плавающим окном.
   «Продолжить вход в режим отладки?» Автоматическое повторное подключение.

## Компонент на стороне мобильного телефона (app/src/remote/java/.../bridge/)

| Документация | Обязанности |
|---|---|
| `BridgeApp` | Вход: установите кран, автоматически переподключите/переустановите, а затем запросите |
| `BridgePrefs` | Адрес/код сопряжения/идентификатор устройства/автоматическое подключение/флаг продолжения (независимые настройки «моста») |
| `WsClient` | Минимальный клиент RFC6455 (непрерывный поток чтения + последовательная запись + объединение сегментов) |
| `BridgeClient` | Цикл сеанса (экспоненциальное повторное подключение), сопряжение, пакетное заполнение журнала + пакет в реальном времени 500 мс, распределение сообщений |
| `BridgeCommands` | Белый список команд: start/stop_connection, get_state, ping |
| `BridgeOverlay` | Перетаскиваемое плавающее окно подсказки (TYPE_APPLICATION_OVERLAY, текст + дополнительная кнопка) |
| `ReinstallFlow` | Загрузить/Проверить/Запросить/Остановить сеанс/PackageInstaller |
| `BridgeSetupActivity` | Второй вход на рабочий стол: адрес + код сопряжения + статус + руководство по разрешениям |
| `InstallReceiver` | Результат установки: Вынести намерение подтверждения системы на главный экран телефона |

## Сервер (cardeck-bridge, внешний склад проекта)

Инструмент MCP: `bridge_status`/`logs_tail(device,lines)`/`logs_fetch(device,since)`
/ `cmd(device,name,args)` / `notify(device,text)` / `offer_apk(device,filePath,version)`.
Переменные среды `PORT`/`PUBLIC_BASE`/`BRIDGE_PAIRING`; `.npmrc` исправлен общедоступный исходный код.

## Цена и договор известны

- `.rd` — новое имя пакета: Shizuku, права на использование уведомлений и разрешения на трансляцию экрана должны быть повторно авторизованы в этом варианте**
  (Описание есть на странице настроек).
— Удаленный вариант не будет включен в основную версию GitHub Release (или явно помечен как экспериментальный), чтобы предотвратить распространение опасений по поводу утечки журналов.
- Журнал содержит имя точки доступа/адрес Bluetooth, который четко указан пользователю в README и приложении.
— Белый список команд расширен за счет включения одноточечного обзора `BridgeCommands`, добавление каких-либо команд оболочки/отражения запрещено.

## Дифференциальное обновление (запущено 24 октября 2026 г., рассчитано на экономию 72–97 % трафика)

Райдеры протестировали пакет несколько раз за один раунд и обнаружили, что полный пакет объемом 15 МБ через сотовую связь слишком дорог. Разность блоков на уровне байтов (стиль rsync):

- **Сервер** (`src/deltadiff.ts`): исторический APK `public/` автоматически строит базовый индекс в соответствии с sha256;
  Устройство hello сообщает sha256 установленного APK (`sourceDir`); базовое попадание генерируется при совершении предложения
  COPY/LITERAL патч (блок FNV-1a 4 КБ + жадное расширение), доход менее 60% от полной суммы генерироваться не будет.
  Фактический размер: 15128 КБ → 440–4223 КБ.
- **Конец устройства** (`bridge/DeltaPatch.kt`): Загрузите исправление → Используйте этот процесс `sourceDir` для базовой сборки.
  → Серьезная проверка продукта sha256 → Войдите в процесс установки. Любой сбой безоговорочно приведет к полной загрузке (разница всего лишь в оптимизации).
- **Контракт соглашения (жесткое соглашение с обеих сторон, не меняйте его отдельно)**: заголовок 88B = Magic(8) + targetLen(8) +
  targetSha(32) + baseLen(8) + baseSha(32); **u64 всегда имеет обратный порядок байтов** (Kotlin на стороне устройства)
  `readLong` только для чтения с прямым порядком байтов — первая версия LE + буфер заголовка 72<88, усечение baseSha, дифференциальный бесшумный возврат к первому прыжку
  Полное количество, исправлено после поимки реальной машины).

## Трехслойный канал журнала (24 октября 2026 г.)

Кольцо памяти (хвост в реальном времени, стандартное подавление шума высокочастотных строк) → диск JSONL (`logs_fetch`, полный объем, кросс-процесс

## Подтверждение установки, тройное страхование и освобождение от налога на плавающие окна (фактическое измерение 24 октября 2026 г.)

- Система подтверждает намерение PENDING_USER_ACTION непосредственно `startActivity` из фонового приемника.
  В Honor оно будет **тихо перехвачено** (без исключений, без интерфейса, без уведомления об ошибке) — условием освобождения является то, что приложение остается в силе.
  **Разрешение плавающего окна (SYSTEM_ALERT_WINDOW)**. При первом использовании пакета `.rd` необходимо включить «Показать в других приложениях»
  «Верхний уровень»: подтверждение установки, подсказки о приостановке отключения и рекомендации по стабильному повторению — все это зависит от него.
- Тройное страхование (`InstallReceiver` + `BridgeSetupActivity`): ① Прямое подтверждение запуска.
  (Действует в течение льготного периода стойки регистрации); ② Откройте страницу настроек отладки и перешлите ее с помощью **Активности переднего плана** (должно вступить в силу);
  ③ Плавающие окна не облагаются налогом. Несмотря на это, принудительная установка по-прежнему требует, чтобы пользователь в этот момент смотрел на свой телефон.
- Дифференциальная информация раскрывается на протяжении всего процесса: журнал приема «Различный пакет XKB», всплывающее окно подтверждения «Различный пакет XKB · Полный пакет YMB».
  (Этот текст появляется только в том случае, если разница действительно успешна, и во время автоматического отката отображается только полный размер пакета).

## Команда сборки (после настройки)

```bash
./gradlew assembleStandardDebug # Ежедневный пакет (эквивалент старого assembleDebug)
./gradlew assembleRemoteDebug # Пакет удаленной отладки (…/remote/debug/app-remote-debug.apk)
./gradlew testStandardDebugUnitTest
./gradlew :app:lintStandardDebug # перехватчик предварительной фиксации синхронизирован
```
