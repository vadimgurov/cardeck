## 1. Два пути доступа

| | Тихий путь (по умолчанию) | Сеть для конкретного приложения (безопасная) |
|---|---|---|
| Триггер | Сидзуку `cmd wifi connect-network` | `WifiNetworkSpecifier` + `requestNetwork` |
| Системные всплывающие окна | **0** | При первом подключении к точке доступа появится окно подтверждения |
| Владение сетью | Система сохранила сеть (видна глобально) | Виден только этому процессу (`Ephemeral`) |
| Требуется Шизуку | Да | Нет |
| Требуется разрешение на размещение | Нет | Требуется для Android 12/12L (13+ заменено NEARBY_WIFI_DEVICES) |
| Для | Нормальное соединение | Когда Шизуку недоступен / щит ROM `connect-network` |

Оба пути в конечном итоге выполняют один и тот же шаг: получают дескриптор `Network` → `bindProcessToNetwork` → перерегистрируют ctrl mDNS.

## 2. Почему нельзя просто использовать `WifiNetworkSpecifier`?

Он связывает «разрешить системе подключиться к Wi-Fi» и «вернуть сеть приложению»: как только спецификатор включен в запрос,
`WifiNetworkFactory` будет называться `isAccessPointApprovedForActiveRequest` до утверждения, все утвержденные источники
(ассоциация CompanionDevice, внутренний утвержденный список точек доступа, предварительное одобрение оболочки) — все они являются ложными, когда появляется окно подтверждения системы**,
На стороне приложения нет API, позволяющего его отключить.

Два распространенных недоразумения:

- **Результат утверждения на самом деле является постоянным**: одобренная точка доступа сохраняется в хранилище конфигурации Wi-Fi в соответствии с именем пакета.
  (`NetworkRequestStoreData`), поэтому "та самая точка доступа" всплывает только первый раз.
- **Невозможно использовать предварительное одобрение оболочки**: `cmd wifi network-requests-set-user-approved <pkg> yes` может
  Укажите пакет для добавления `mApprovedApp` (тогда запрос спецификатора выдается напрямую, без открытия окна; но это глобальное одно значение,
  Одобрение этого приложения вытеснит другие приложения), но этой команды нет в `WifiShellCommand.NON_PRIVILEGED_COMMANDS`**
  Здесь выполнение uid 2000 выдаст `SecurityException: Uid 2000 does not have access to ...` (требуется root).
  Так что Шизуку использовать нельзя.

Вывод: если вы хотите добиться «0 всплывающих окон после смены машины, переустановки и очистки данных», то можно только обойти спецификатор и позволить системе подключиться самостоятельно.

## 3. Две двухступенчатые практические ямы.

`WifiShellCommand.connect-network` просто передает конфигурацию `WifiService.connect(...)` на `return 0`,
Даже не жду `IActionListener`. Поэтому **должен** опрашивать `cmd wifi status`, пока он не появится.
`Wifi is connected to "<SSID>"` (отключить старую сеть → сканирование → ассоциирование → DHCP измеряется 2–10 с, на 5 ГГц дольше).
Окно в коде - 25с (`CAR_WIFI_JOIN_WAIT_MS`), которое можно сразу прервать "отменой соединения".

При его написании нет побочных эффектов, и он зарезервирован для семантической ясности. **Настоящая гарантия отсутствия всплывающих окон — «отсутствие спецификатора»**.

## 4. Зачем еще нужен `bindProcessToNetwork`?

Интуитивно «достаточно просто передать `Network` в NsdManager/`socketFactory`». Этот проект не может этого сделать по трем причинам:

1. **Рассылка mDNS не имеет API-интерфейса для конкретной сети**: `NsdManager.registerService(NsdServiceInfo, int,
   RegistrationListener)` не имеет параметра Network (вновь добавленный в API 36 перегрузка AdvertisingRequest;
   Этот проект компилирует SDK 34). Зарегистрируйтесь и следуйте **Сети по умолчанию** —— Не привязано к процессу, `_carplay-ctrl._tcp`
   Просто отправь его с сотового телефона, машина никогда не найдет телефон, и не придет ни `GET /ctrl-int/1/connect`, ни 0x4301.
   (Новые API на стороне обнаружения обеспечивают перегрузку `discoverServices(..., NetworkRequest, ...)`, но не на стороне широковещания.)
2. **Несколько голых сокетов во всем проекте**: управление/событие AirPlay, видео TCP, аудио UDP, сервер синхронизации,
   Сервер управления — `Socket()` / `DatagramSocket()`, основанный на сети процесса по умолчанию.
3. **Влияет только на этот процесс**: `bindProcessToNetwork` действует на сокет (тот же, что и UID) вызывающего процесса, а не на системном уровне.
   настройки. Навигация/музыка на виртуальном экране автомобиля – это **независимый процесс**, он использует сеть по умолчанию (сотовую), как обычно, и не будет отключен.
   Реальная цена заключается лишь в том, что «собственные» интернет-запросы CarDeck (URL-адреса медиа-обложки) также проходят через Wi-Fi автомобиля во время сеанса —
   Это полностью соответствует поведению в эпоху спецификаторов и не связано с этим изменением.

## 5. `cmd wifi set-wifi-watchdog-enabled false` не существует

AOSP `WifiShellCommand` содержит только:

```
set-wifi-watchdog <true|false> # Функция WifiLastResortWatchdog (самоспасение после постоянного сбоя соединения)
get-wifi-watchdog
```

Оба **не** `NON_PRIVILEGED_COMMANDS`, оболочка (uid 2000) при выполнении выдаст SecurityException.
Только root может работать; и то, что ему удается, это «спасти себя, если вы не можете подключиться», а не «отключиться, если нет внешней сети». Хочу выключить
«Автоматическое переключение без внешней сети» требует интеллектуального сетевого переключения OEM (у Honor/Xiaomi/OPPO есть собственный вход), универсального не существует.

## 6. Стоимость сохранения на уровне системы (это компромисс дизайна, а не ошибка)

- Точка доступа входит в «системную сохраненную сеть»: она автоматически подключается в следующий раз, когда входит в диапазон - поэтому второе соединение не требует никаких действий;
  Автоматически отключается после выхода из автомобиля.
- Сеть по умолчанию по-прежнему сотовая: у этого Wi-Fi нет `VALIDATED`, `Active default network` им не станет,
  Другие приложения используют 4G/5G как обычно (Wi-Fi на уровне системы ≠ сеть по умолчанию).
- Некоторые ПЗУ выдают сообщение «Эта WLAN не может получить доступ к Интернету» и даже предоставляют кнопку «Переключиться обратно на мобильные данные»; это принадлежит производителю
  Пользовательский интерфейс нельзя закрыть единообразно с помощью оболочки.
- Хотите отменить: «Забудьте» точку доступа в настройках WLAN системы или
  `cmd wifi list-networks` `cmd wifi forget-network <id>` после проверки netId.
