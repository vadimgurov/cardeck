# Физический экран мобильного телефона (реальный экран) + виртуальный экран независимый и всегда включенный

> 23 октября 2026 г. Цель: положить телефон в карман с черным экраном и взаимодействовать с автомобилем со скоростью 60 кадров в секунду, как обычно.
> Код: `shizuku/CarInputServiceImpl.setPhysicalScreenPower` +
>`SessionController.enterPhoneScreenOff`.

## 1. Почему бы не «нажать кнопку питания»

Нажмите кнопку питания/вызовите `PowerManager.goToSleep`, чтобы войти в режим **Блокировка экрана + сон**:

- Keyguard блокирует виртуальный экран (автомобиль видит заблокированный экран или черный экран);
- Регулирование/зависание процессора, остановка потоков кодировщика и протокола.

`-S/--turn-screen-off` Scrcpy идет по другому пути: **Системная логика остается «на экране и разблокирована»**,
Отключите питание только физической панели на уровне SurfaceFlinger. CarDeck копирует этот подход.

## 2. Три ключевых момента

### 2.1 Виртуальный экран должен находиться в независимой группе дисплеев

Доверенный виртуальный экран (app/appHi/map) объявляет два дополнительных флага @hide:

| Флаг | Значение | Роль | Дополнительные разрешения |
|---|---|---|---|
| `OWN_DISPLAY_GROUP` | `1<<11 = 0x800` | Виртуальный экран входит в свою собственную группу DisplayGroup, и главный экран не отключается при переходе в режим сна/выключении питания | `ADD_TRUSTED_DISPLAY` (изначально требуется доверенный экран) |
| `ALWAYS_UNLOCKED` | `1<<12 = 0x1000` | Экран не прорисовывается, когда экран заблокирован Keyguard | `ADD_ALWAYS_UNLOCKED_DISPLAY` (**Некоторые ПЗУ не передаются в оболочку**) |

`DisplayManagerService.createVirtualDisplayInternal` имеет явную проверку разрешений для них обоих. Если разрешение отсутствует, напрямую
`SecurityException`. Таким образом, `createDisplay` — это **понижение третьего уровня**: `независимая группа+ALWAYS_UNLOCKED` →
`Независимая группа` → Базовые флаги, любой сбой уровня 1 останется следы и сохранится, а весь экран не зависнет.

Обратите внимание, что `PUBLIC` неявно добавит `AUTO_MIRROR`, а `AUTO_MIRROR` очистит `OWN_DISPLAY_GROUP`——
Мы также объявили `OWN_CONTENT_ONLY` (сброшено AUTO_MIRROR), чтобы можно было сохранить независимую группу дисплеев.

**Экраны док-станции также должны быть сгруппированы независимо** (фактическое тестирование состоялось 23 октября 2026 г.): док-станция — это **ненадежный** экран. Изначально требовались только базовые флаги.
Таким образом, он попадает в группу дисплеев по умолчанию: как только физическая панель отключается, вся группа гаснет, а на стороне автомобиля отображается: «Экран приложения нормальный, а панель док-станции вся черная».
Восстановление после разблокировки». Модификация заключается в добавлении `OWN_DISPLAY_GROUP` (с откатом) в док:
AOSP очищает этот флаг только при `AUTO_MIRROR`, а `AUTO_MIRROR` автоматически устанавливается только при `PUBLIC`.
Док не декларирует `PUBLIC`, поэтому флаг сохранится; Для `OWN_DISPLAY_GROUP` требуется только `ADD_TRUSTED_DISPLAY`,
"Недоверенная" семантика дока не изменена (сторонние задачи по-прежнему нельзя загружать).

### 2.2 Физическое отключение панели: `SurfaceControl.setDisplayPowerMode`

Настройте **токен физического главного экрана** `setDisplayPowerMode(token, 0)` (0=ВЫКЛ, 2=НОРМАЛЬНО).
Рамка все еще думает, что экран включен → не блокирует экран и не входит в режим дремоты; Сенсорная микросхема также отключается вместе с панелью, и случайные прикосновения из карманов недействительны.

**Способ получения токенов изменился в Android 14** (это самая простая ошибка):

- SDK ≤ 33: `SurfaceControl.getInternalDisplayToken()`, резервный маршрут
  `getPhysicalDisplayIds()` + `getPhysicalDisplayToken(id)`;
- SDK ≥ 34: указанный выше метод был удален из SurfaceControl и может использоваться только
  `com.android.server.display.DisplayControl`. Он находится в `services.jar` и не виден обычным загрузчикам классов.
  Вы должны использовать `ClassLoaderFactory.createClassLoader(SYSTEMSERVERCLASSPATH, ...)` для создания загрузчика классов.
  Затем `Runtime.loadLibrary0(cls, "android_servers")` регистрирует метод JNI (так же, как scrcpy).

### 2.3 Не спать и отключать экран

- `CarPlayService` уже удерживает блокировку `PARTIAL_WAKE_LOCK` + WiFi с низкой задержкой во время сеанса, поэтому добавлять ее нет необходимости;
- `ScreenDimmer` установил `screen_off_timeout` на максимальное значение во время сеанса и восстановил его в конце,
  Таким образом, рамка не приведет к выключению экрана сама по себе (в противном случае изменение состояния группы снова зажжет панель).

## 3. Выбор времени

```
Начинается push-стриминг (построен виртуальный экран)
  → Если «True screen при подключении» выключен: останется только темный экран, пропустите следующие шаги
  → Если телефон находится в спящем режиме: введите keyevent KEYCODE_WAKEUP → Подождите 400 мс → wm ignore-keyguard (наилучшая попытка)
  → setPhysicalScreenPower(false) // Выключение панели
  → phoneScreenOff = true

Отключение на стороне автомобиля (VideoSender.onEnded)
  →restorePhoneScreen(sleep=true) //Оставляем панель черной, непосредственно KEYCODE_SLEEP
Отключение/завершение сеанса вручную (retireSession)
  →restorePhoneScreen(sleep=false) //Панель загорается (человек перед телефоном)
```

## 3.1 Установите переключатель

**Настройки → Дисплей → Истинный экран при подключении (вкл./выкл., по умолчанию выкл., запрос пользователя от 24 октября 2026 г.)**, постоянство в
`DisplayPrefs.screenOffOnConnect` (общее предпочтение `settings`, ключ `screen_off_on_connect`).

### 3.2 Обнаружение касания осуществляется по темному экрану (фактическое измерение пользователем 24 октября 2026 г.)

**Сенсорная микросхема все еще работает** после выключения панели (Фактическое тестирование на Honor Magic7: нажмите кнопку настроек под черным экраном, и прикосновение будет прямым.
UI и подсветка программно). Таким образом, автоматический путь не предполагает простого отключения электроэнергии, а повторно использует весь ручной процесс ложного экрана темного экрана.
(`ScreenDimmer.enterDimNow`): Включите темный экран → отключите питание панели → **Нажмите на темный экран, чтобы проснуться**
(onUserInteraction → восстановить питание + убрать темный экран). Темный экран также является **Карманным щитом** – без него
Касаясь в кармане, вы нажмете на приложение на переднем плане (например, «Отключить»). Нажатие кнопки питания по-прежнему запускает режим истинного сна (Keyguard/
Отслаивание поверхности нестабильно, и во время реальных испытаний 24 октября 2026 года автомобиль замерз. Правильная поза — проснуться, нажав на темный экран и не нажимая кнопку питания.
Когда темный экран недоступен (отсутствие разрешения плавающего окна), его версия будет понижена и питание отключено — метода сенсорного пробуждения нет, вы можете только нажать кнопку питания.

- После выключения: панель больше не будет отключаться при установлении сеанса, сохранится только исходный темный экран 45с + постоянный свет;
- **Переключение вступает в силу немедленно** (`SessionController.applyScreenOffPreference`): даже когда панель темная, она может
  Выключите его в панели настроек **Car Screen**, и телефон загорится сразу, не дожидаясь следующего подключения;
- Переключение без сеанса не вызывает никаких действий.

## 4. Известные ограничения (ни одно из них не является ошибкой, это неотъемлемая часть этого механизма)

1. **Для включения необходимо дважды нажать кнопку питания**: рамка считает, что экран включен. Первое нажатие кнопки питания означает «выключение экрана», а второе — «включение экрана».
   Это то же самое поведение, что и scrcpy; реального риска кирпичной кладки нет.
2. **Защитный замок (PIN/шаблон) невозможно разблокировать**: `wm dismiss-keyguard` недействителен для защитного замка. виртуальный экран
   Keyguard не влияет на `ALWAYS_UNLOCKED`; однако вам все равно придется разблокировать его вручную, чтобы открывать приложения и принимать звонки на телефоне.
3. **Экран отката на стороне приложения (EMUI и т.п.) не гарантируется**: Экран отката не имеет независимой группы отображения, и продолжает ли вывод кадра после выключения экрана зависит от ПЗУ.
   В логе вы увидите `ЭКРАН: Физический экран выключен`, но экран автомобиля может зависнуть - для этого типа ПЗУ рекомендуется отключить эту функцию.
4. **Процесс завершается ненормально**: UserService является резидентным процессом оболочки, и его состояние питания не исчезает вместе с процессом приложения.
   Существует три уровня безопасности: восстановление после завершения сеанса, восстановление до истечения срока действия службы и самоуничтожения, а также восстановление после следующего запуска приложения.
5. **Некоторые прошивки не выдают оболочку `ADD_ALWAYS_UNLOCKED_DISPLAY`**: она появится в журнале
   `Ошибка с ALWAYS_UNLOCKED – переход в независимую группу` на виртуальном экране, когда экран заблокирован.

## 5. Устранение неполадок

Журнал процесса оболочки находится по адресу `/data/local/tmp/carinput_svc.log`:

```
createDisplay(CarPlayApp) доверенная+независимая группа+флаги ALWAYS_UNLOCKED=0xc48
createDisplay(CarPlayApp) флаги доверенной+независимой группы=0xc08
ДисплейКонтроль готов.
setPhysicalScreenPower(false) ok=true
setPhysicalScreenPower(true) ok=true
```

Сторона приложения (`files/main_debug.log`):

```
ЭКРАН: физический экран выключен (реальный экран; система продолжает работать, виртуальный экран отображается как обычно, его можно восстановить, дважды нажав кнопку питания)
ЭКРАН: физический экран не выключился (ПЗУ не дало разрешения оболочке/не удалось получить токен отображения) – продолжайте использовать темный экран
ЭКРАН: Сторона автомобиля отключена - телефон переведен в режим сна (панель остается темной)
ЭКРАН: Физический экран снова стал светиться ok=true
```

## 6. Как откатиться назад

1. **Уровень пользователя**: Настройки → Дисплей → Переключите параметр «Истинный экран при подключении» на «Выкл.» (вступает в силу немедленно, останется только темный экран);
2. Если хотите откатиться вместе с флагами: удалите флаги в `CarInputServiceImpl.createDisplay`
   `FLAG_OWN_DISPLAY_GROUP or FLAG_ALWAYS_UNLOCKED` (попытка первого уровня), цепочка понижения будет автоматически использовать базовые флаги.
